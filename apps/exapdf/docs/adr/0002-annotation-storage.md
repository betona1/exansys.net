# ADR-0002. 주석 저장: 앱 SQLite 오버레이 + 내보내기

- 상태: 채택 (2026-08-01)

## 배경
두 진영 모두 사용자 불만이 존재한다.
- DB 저장(Zotero, Sioyek): 빠르고 태그/필터/동기화 자유. 단 **"다른 뷰어에서 안 보인다"**
- PDF 임베드(Skim, Highlights): 이식성 최고. 단 **태그/필터/동기화 약함**, 파일 재작성 리스크

또한 채택한 QtPdf 는 주석 생성/편집을 지원하지 않는다.

## 결정
**SQLite 를 정본으로 하고, "주석 포함 PDF 굽기"를 1급 기능으로 제공한다.**
- 원본 PDF 파일은 **절대 수정하지 않는다**
- Zotero 와 같은 방어 논리를 명시: *언제든 주석 포함 PDF 로 내보낼 수 있으므로 락인이 아니다*

## 앵커 설계 (중요)
페이지 번호 + 좌표만 저장하면 파일이 갱신될 때 전부 깨진다. 다음을 함께 저장한다.

| 필드 | 용도 |
|---|---|
| page_no, rects(JSON) | 1차 렌더 위치 |
| anchor_text | 하이라이트된 원문 |
| prefix_text / suffix_text | 앞뒤 문맥 각 40자 |
| text_hash | 빠른 동일성 판정 |

파일 해시가 달라지면 anchor_text + 문맥으로 퍼지 재매칭 후 좌표를 갱신하고,
실패 시 "위치를 잃은 주석" 목록으로 사용자에게 노출한다.

## 내보내기
- Markdown / Obsidian — **`exapdf://book/{id}/page/{n}?anno={uuid}` 딥링크 필수**
  (딥링크 없이 내보낸 노트는 원문으로 못 돌아가는 죽은 텍스트가 된다)
- 주석 포함 PDF 굽기 (pypdf `add_annotation`, 사본 생성)
- JSON / CSV 원시 데이터

---

## 보강 (2026-08-01, Flutter 전환)

### 내보내기를 3종으로 나눈다
`굽기(flatten)` 하나로는 부족하다. flatten 된 주석은 **Acrobat 등에서 다시 편집할 수 없다.**
- **표준 PDF 주석 내보내기** — 서버(pikepdf)가 실제 `/Annots` 딕셔너리(`/Highlight`,`/Text`)를
  써 넣는다. 타 앱에서 재편집 가능 → 락인 방지
- **굽기(flatten)** — 보기 전용 공유용
- **Markdown/Obsidian · JSON/CSV**

### 파일이 바뀌었을 때 (확정)
`document_checksum` 불일치 시 **자동 퍼지 재부착**을 시도한다.
`anchor_text` + 앞뒤 문맥 40자로 같은 문구를 찾아 좌표를 갱신하고,
실패한 것만 `is_orphan=1` 로 표시해 주석 목록 상단에 **주황 경고 그룹**으로 모은다.
사용자는 거기서 수동으로 위치를 지정하거나 삭제한다.

### 원본에 이미 있던 주석
읽기 전용으로 **회색 계열**로 렌더해 내 주석과 시각적으로 구분한다. 편집하지 않는다.
설정에서 `원본 주석 표시` 를 끌 수 있다.

### 동기화는 append-only 이벤트로
주석의 생성/수정/삭제를 각각 레코드로 남기면 여러 기기 병합이 자동으로 되고
**충돌 해결 UI 자체가 필요 없어진다.** 실제로 충돌하는 것은 읽던 위치 하나뿐이고
그건 최신 우선(LWW)으로 충분하다.
