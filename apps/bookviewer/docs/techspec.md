# techspec.md — BookViewer (북뷰) UI/UX 기술 명세 v0.2 (Flutter)

`SPEC.md` 가 "무엇을 만드는가", `BRAND.md` 가 "어떤 얼굴인가"라면
이 문서는 **"화면에 무엇이 놓이고 어떤 버튼이 무엇을 하는가"** 다.

버튼 ID(`btn.*`)와 액션 ID(`act.*`)를 **Dart 상수명으로 그대로** 쓴다.
색·간격·폰트는 여기서 값을 직접 쓰지 않고 `BRAND.md` 토큰을 참조한다.

---

## 1. 설계 원칙

1. **읽는 화면이 주인공이다.** 기본 상태에서 페이지가 화면의 88% 이상.
   툴바는 **탭하면 사라진다**(몰입 모드). Acrobat 이 "무겁다"고 욕먹는 길을 반복하지 않는다
2. **모든 기능은 3단계 안에.** 툴바 → 시트 → 실행
3. **파괴적 동작이 없다.** 원본 PDF 를 건드리는 버튼은 존재하지 않는다
4. **상태는 EXA 가 말한다.** 진행률·인덱싱·변환은 캐릭터 표정 + 한 줄 카피로 (BRAND.md §6.3)
5. **터치와 포인터를 둘 다 1급으로.** 같은 기능에 제스처와 단축키를 각각 매핑한다
6. **서버가 죽어도 읽기는 100% 된다.** 서버 의존 기능만 비활성 + 안내

## 2. 반응형 3분기

**기기 종류가 아니라 폭으로 분기한다.** 폴더블·분할화면에서 기기 판정은 반드시 틀린다.

| 분기 | 폭 | 대표 | 레이아웃 |
|---|---|---|---|
| **compact** | < 600dp | 폰 | 전체화면 리더. 패널은 **바텀시트**. 하단 네비 바 |
| **medium** | 600~1023dp | 태블릿 세로, 폴더블 | 리더 + **접히는 좌측 레일**. 패널은 사이드시트 |
| **expanded** | ≥ 1024dp | 태블릿 가로, 데스크톱 | 좌측 패널 + 뷰포트 + 우측 패널 상주. **탭바 노출** |

- **두 페이지 펼침은 medium 이상에서만** 자동 활성 (compact 에서는 강제 해제)
- 좌우 분할(스플릿)은 **expanded 전용**
- 데스크톱은 expanded 에 **탭 + 키보드 단축키 + 우클릭 메뉴**를 추가로 얹는다

## 5. 제스처 · 단축키 매핑

**같은 기능을 터치와 포인터 양쪽에서 낼 수 있어야 한다.**

| 기능 | 터치 | 포인터/키보드 |
|---|---|---|
| 페이지 넘김 | 좌우 스와이프 / 화면 가장자리 탭 | `←` `→` `PgUp` `PgDn` / 휠 |
| 줌 | 핀치 / 더블탭 | `Ctrl+휠` / `Ctrl` `+` `-` `0` |
| UI 숨김·표시 | 화면 중앙 탭 | `F11` / `Esc` |
| 텍스트 선택 | 롱프레스 후 핸들 드래그 | 드래그 |
| 캡처 | 두 손가락 롱프레스 or 툴바 | `Ctrl+Shift+C` |
| 페이지 점프 | 하단 슬라이더 드래그(미리보기 썸네일 표시) | `Ctrl+G` |
| 컨텍스트 메뉴 | 롱프레스 | 우클릭 |
| 검색 | 툴바 | `Ctrl+F` / `Ctrl+Shift+F` |
| 하이라이트 색 | 선택 후 색 칩 | `1`~`5` |
| 사이드패널 | 좌측 엣지 스와이프 | `Ctrl+B` |

#### 6.2-1. 좌우 나눠 보기 (`btn.splitPages`)

책을 펼친 채로 스캔하면 PDF 한 장에 왼쪽 쪽과 오른쪽 쪽이 같이 들어간다.
그대로 보면 폰에서 글자가 절반 크기가 되어 읽을 수 없다.
실제 표본(`나를잃어가면서지켜야할관계는없다.pdf`)이 1331 × 717 로 가로가 더 길었다.

- 문서를 열 때 **첫 쪽의 가로가 세로의 1.2배를 넘으면** 감지해서 배너로 권한다.
  거절하면 다시 묻지 않는다 (`book_settings.split_prompted`)
- 쪽 번호는 그대로 두고 반쪽 단위로 넘긴다. 하단 바에 `12 / 102 (좌)` 처럼 표시
- `split_right_to_left` 로 오른쪽부터 읽는 책에 대응
- 자르는 순서는 **여백 크롭 → 반 나누기**. 반대로 하면 가운데 제본 여백이 남는다

#### 6.4-1. 여백 크롭 구현 (확정)

- **감지**: 쪽을 160px 폭으로 그려 흰 배경이 아닌 픽셀의 바운딩 박스를 찾는다.
  원본 해상도로 하면 300쪽 문서에서 몇 십 초가 걸린다
- **홀·짝 따로**: 제본 여백이 좌우로 번갈아 나오므로 하나로 합치면 한쪽이 잘린다
- 표본 여러 쪽 중 **가장 적게 자르는 값**을 쓴다. 평균을 쓰면 표제지처럼 여백이 큰 쪽
  때문에 본문 글자가 잘린다
- **잡티 제거**: 한 줄에서 최소 2픽셀 이상 어두워야 내용으로 본다.
  비율(1%)만 쓰면 160px 렌더에서 1픽셀로 떨어져 먼지 한 점에 크롭이 무력해진다
- 여유 패딩 1.2% 를 남기고, 한쪽으로 45% 넘게 자르지 않는다
- **자동 감지 결과를 바로 적용하지 않는다.** 감지 후 조정 시트를 함께 띄운다 —
  자동 판정은 반드시 틀리는 쪽이 나오고, 그때 "페이지 번호가 잘렸다"로 직행한다

> **제약**: 크롭·분할을 켜면 쪽을 직접 그리는 뷰어로 바뀌어 **글자 선택과 검색
> 하이라이트가 되지 않는다.** `PdfViewer` 로는 쪽을 잘라 배치할 수 없기 때문이다.
> 스캔본은 텍스트 레이어가 없어 손해가 없지만, 텍스트 PDF 에서는 트레이드오프다.
> 그래서 기본으로 켜지 않고 감지해서 물어본다.
| `btn.tts` | `volume-2` | 읽어주기 | `Ctrl+Shift+S` | 토글 | 재생 중 미니 플레이어 바 |
| `btn.translate` | `languages` | 번역 | `Ctrl+T` | 토글 | 서버 필요 — 오프라인 시 비활성 + 사유 표시 |
| `btn.split` | `columns-2` | 좌우 분할 | `Ctrl+\` | 토글+시트 | **expanded 전용** |
| `btn.more` | `more-vertical` | 더보기 | `F10` | 메뉴 | §7 |

### 6.5 서버 의존 버튼 규칙
`btn.translate`, `표 추출`, `OCR 실행`, `영상→북`, AI 탭은 서버가 필요하다.
**연결 불가 시 숨기지 않고 비활성 + 사유를 보여준다.** 사라지면 사용자는 기능이 없다고 오해한다.
표시: 아이콘 흐리게 + 툴팁 `서버에 연결할 수 없습니다 · 다시 시도`.

## 8. 테마 시트 (`btn.theme`)

```
◐ 테마
  ○ 라이트   ● 다크   ○ 세피아   ○ 시스템 따름
─
다크모드에서 이미지 처리
  ○ 전체 반전            사진이 네거티브가 됩니다
  ● 이미지 원본 유지     ← 기본값
  ○ 이미지 살짝 어둡게
─
□ 이 문서에만 적용
  밝기  ──────●────  92%
  대비  ────●──────  100%
```

**구현 메모** — 단순 반전은 사진·그래프를 망가뜨린다. 조사한 뷰어들의 **최대 불만 지점이자 우리의 차별화**다.

### 확정된 구현 (2026-08-01)

휘도만 반전한다. 색상은 남긴다.

```
C' = C - 2L + 1        (L = 0.2126R + 0.7152G + 0.0722B)
```

흰 종이는 검게, 검은 글자는 희게 가면서 색조는 유지된다.
`1 - x` 로 뒤집으면 빨강이 청록이 되고 사진이 네거티브가 된다 — 그것이 바로 그 불만이다.

**이미지 bbox 는 쓸 수 없다.** pdfrx 가 이미지 객체 좌표를 제공하지 않는다
(텍스트·링크·구조화 텍스트만). 그래서 어디가 사진인지 **채도로 가려낸다** —
픽셀의 `max(R,G,B) - min(R,G,B)` 가 46 을 넘으면 사진으로 보고 밝기만 낮춰 남기고,
회색에 가까우면(= 스캔한 글자·선) 뒤집는다.

- 스캔한 누런 종이(238,232,216)는 채도가 낮아 제대로 뒤집힌다. 이것을 사진으로
  오해하면 다크 리딩이 통째로 망가지므로 테스트로 고정했다
- 색 행렬만으로는 이 조건 분기를 할 수 없어 **픽셀을 직접 만진다.**
  `compute()` 로 아이솔레이트에 넘겨 UI 를 막지 않는다 (CLAUDE.md §5)
- 따라서 다크 리딩을 켜면 크롭·분할과 마찬가지로 직접 렌더 모드가 되어
  **글자 선택·검색 하이라이트가 되지 않는다**

## 9. 캡처 모드

1. 진입하면 십자선 커서(포인터) 또는 반투명 가이드(터치). 상단 힌트 바
   `드래그해 영역 선택 · 뒤로 취소`
2. 드래그 중 선택 밖 60% 어둡게. 하단에 **픽셀 크기 + 출력 해상도** 실시간 표시
   `842 × 460 px · 600dpi 출력 시 3508 × 1917`
3. 손을 떼면 액션 바:

| 버튼 | 아이콘 | 키 | 동작 |
|---|---|---|---|
| 복사 | `clipboard-copy` | `Enter` | **화면 픽셀이 아니라 재렌더**. 기본 300dpi |
| 이미지 저장 | `image-down` | `Ctrl+S` | 마지막 폴더/앨범 기억 |
| 공유 | `share-2` | — | 모바일 시스템 공유 시트 |

## 11. 문서 내 검색

```
┌ 🔍 [ 정규화              ]  ‹ 3/27 ›  Aa  W  .*  ✕ ┐
```
- `Aa` 대소문자 · `W` 전체 단어 · `.*` 정규식
- 결과는 반투명 노랑, **현재 결과만 주황 테두리**
- 스크롤바 옆에 결과 위치 눈금(미니맵)
- compact 는 결과 목록을 바텀시트로: `p.128 …텍스트 **정규화**를 거치지…`
- **결과 0건 + 텍스트 레이어 없음** → EXA `error` + 배너
  `이 문서는 스캔본으로 보입니다. OCR 을 실행할까요?`

## 17. 상태 · 피드백 (EXA 연동)

| 상황 | 처리 |
|---|---|
| 페이지 로딩 | 정확한 크기의 회색 플레이스홀더 + 은은한 shimmer. **스피너 금지**(레이아웃이 튄다) |

| 오류 | **"무엇이 실패 / 가능한 원인 / 다음 행동" 3요소를 반드시 갖춘다.** EXA `error` |
| 암호 PDF | 비밀번호 입력 다이얼로그 + `이 기기에 기억` |

## 18. 작업(Job) 화면 — 서버 변환

영상→북, OCR, 표 추출은 오래 걸린다. **재개 가능해야 한다.**

```
┌ 변환 작업 ──────────────────────────────────┐
│ (EXA think)  딥러닝 강의 3강                 │
│   ●───●───●───○───○───○                     │
│   자막  전사  슬라이드  OCR  조판  완료       │
│   슬라이드 찾는 중 · 42/180 프레임           │
│   [ 일시정지 ]  [ 취소 ]                     │
├─────────────────────────────────────────────┤
│ ✓ 통계학 특강 1강        어제 · PDF 열기      │
│ ✕ 선형대수 5강           실패 · 다시 시도     │
└─────────────────────────────────────────────┘
```
- 단계별 체크포인트를 서버에 남겨 **죽은 단계부터 재개**한다
- 실패는 사유를 그대로 보여준다 (`자막 없음 → 전사 필요`, `영상 비공개` 등)

## 19. 접근성

- 모든 아이콘 버튼에 `Semantics(label:)` + 툴팁(단축키 포함)
- 최소 터치 타깃 **48×48dp**
- 포커스 링은 `action #2F6BFF` 2px. 절대 제거하지 않는다
- 본문 대비 4.5:1 이상 (세 테마 전부 검증). **앰버는 텍스트에 쓰지 않는다**
- 색만으로 의미를 전달하지 않는다 — 하이라이트 색에 라벨 병기
- `MediaQuery.disableAnimations` 존중. EXA 애니메이션도 정지
- 시스템 폰트 크기 배율(최대 2.0x)에서 레이아웃이 깨지지 않아야 한다
