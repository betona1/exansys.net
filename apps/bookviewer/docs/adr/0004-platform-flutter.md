# ADR-0004. 플랫폼: Flutter (Android 우선 + 데스크톱 동시)

- 상태: 채택 (2026-08-01)

## 배경
초기 설계는 PySide6 Windows 데스크톱이었다. 이후 다음이 확정됐다.
- 제작사 **EXANSYS 는 모바일 앱 개발사**다
- 언어는 **Flutter** 를 쓴다
- **데스크톱 앱도 함께** 개발한다
- 1차 타깃은 **Android 폰·태블릿**

## 결정
Flutter 단일 코드베이스로 Android → 데스크톱(Windows/macOS) 순으로 낸다.

### 이 결정이 강제하는 것
1. **무거운 처리는 전부 서버로 간다.** yt-dlp / ffmpeg / whisper / OCR 은 모바일에서 돌지 않는다.
   → Django + MySQL 서버가 파이프라인을 담당하고, 앱은 결과 PDF 를 받아 읽는다
2. **앱에 DB 접속정보를 넣을 수 없다.** 클라이언트 번들은 디컴파일 가능하다.
   앱은 Django API 만 호출한다
3. **레이아웃을 3분기로 설계한다.** compact(<600) / medium(600~1024) / expanded(≥1024).
   기기 종류가 아니라 폭으로 분기한다 (폴더블·분할화면 대응)
4. **입력 방식이 두 벌이다.** 터치(탭·롱프레스·핀치·스와이프)와 포인터(호버·우클릭·키보드)를
   같은 기능에 각각 매핑한다. → `docs/techspec.md`

## 대가
- Flutter 의 PDF 생태계는 네이티브만큼 두껍지 않다 → pdfrx 하나에 의존한다(ADR-0001)
- 데스크톱 Flutter 는 파일 시스템·창 관리에서 손이 더 간다
- 서버 의존이 생긴다 → **서버 없이도 "PDF 읽기"는 100% 동작해야 한다.** 이건 설계 제약이다

## 기각
- Kotlin + Compose (Android 전용): 데스크톱 동시 요구와 불일치.
  참고로 `androidx.pdf` 는 2026-04 기준 여전히 `1.0.0-alpha18` 이고 주석 쓰기 API 가 없다.
  Room 은 FTS3/FTS4 만 지원해 **FTS5 가 없어 한국어 검색이 조용히 실패**한다
- PySide6: 모바일 불가
