# TECHSPEC — BookViewer (북뷰)

PDF로 저장한 책을 책처럼 읽는 생산성 리더.
**이 문서는 초안이다.** 확정 표시(✅)가 없는 항목은 사용자 승인 전이다.

---

## 1. 무엇을 만드는가

스캔했거나 내려받아 둔 PDF 책이 폰·태블릿에 쌓여 있는 사람을 위한 앱이다.
기본 PDF 뷰어로는 **책처럼 읽기 어렵고**, 원하는 문장을 **찾기 어렵고**,
좋은 구절을 **남기기 번거롭다**. 그 세 가지를 해결한다.

### 이런 사람을 위해
- 전공 서적·논문·매뉴얼을 PDF로 들고 다니며 반복해 들춰 보는 사람
- 밑줄 긋고 싶은 구절을 메모 앱이나 대화창에 옮겨 적는 사람
- "그 내용 어디 있었더라" 하며 페이지를 손으로 넘겨 찾는 사람

### 이번 범위가 아닌 것
- PDF 편집·서명·양식 채우기 (읽기 전용)
- 전자책 스토어·구매
- 계정·클라우드 동기화 (MVP 제외)

## 2. 핵심 기능

### 2-1. 책처럼 보기
- 페이지 넘김 — 가로 스와이프(책 넘기듯) / 세로 스크롤 중 선택
- 두 쪽 보기 — 가로 화면·태블릿에서 좌우 펼침
- 진행률 — 현재 쪽 / 전체 쪽, 남은 분량 표시
- 이어 읽기 — 마지막으로 본 쪽에서 다시 시작
- 리딩 테마 — 밝게 / 어둡게 / 세피아, 밝기 조절

### 2-2. 검색
- 문서 전체 텍스트 검색, 결과 목록에서 해당 쪽으로 이동
- 검색어 하이라이트, 이전·다음 결과 이동
- 큰 문서는 색인을 미리 만들어 두고 재검색은 즉시 응답
- 텍스트가 없는 스캔 PDF는 검색 불가임을 명확히 알린다 (OCR은 이번 범위 밖)

### 2-3. 캡처
- 화면에서 원하는 영역을 사각형으로 잘라 이미지로 저장
- 저장 / 공유 / 클립보드 복사
- 출처(책 이름·쪽 번호)를 이미지 하단에 함께 넣을지 선택

### 2-4. 글자 복사
- 본문 텍스트를 드래그로 선택 → 복사
- 선택 영역을 하이라이트로 저장 (책갈피 목록에 남음)
- 복사 시 출처(쪽 번호)를 같이 붙일지 설정

### 2-5. 내 책장
- 최근 읽은 책, 진행률과 함께
- 책갈피·하이라이트 모아 보기
- 파일은 사용자가 고른 위치를 참조한다. 앱이 원본을 옮기거나 복사하지 않는다

## 3. 기술 선택 (검증 필요)

| 항목 | 제안 | 확인해야 할 것 |
|---|---|---|
| 프레임워크 | Flutter (Android 우선) | VibeQuest와 같은 전략 |
| PDF 엔진 | `pdfrx` | 텍스트 추출·검색·선택이 실제로 되는지 |
| 로컬 DB | Drift + SQLite | 책갈피·진행률·검색 색인 저장 |
| 파일 접근 | 시스템 파일 피커 (SAF) | 저장소 전체 권한 없이 동작하는지 |
| 캡처 | 화면 영역 렌더 → PNG | 고해상도로 잘리는지 |

**1단계에서 할 일**: 위 표의 "확인해야 할 것"을 실제 코드로 검증한다.
특히 PDF 엔진이 텍스트 레이어를 다루지 못하면 검색·복사가 성립하지 않으므로,
여기서 막히면 엔진을 바꾸거나 범위를 다시 잡는다.

## 3-1. PDF 엔진 검증 결과 (1단계 완료)

`app/lib/main.dart` 검증 앱, 표본 문서 `data/sample_book.pdf`(4쪽, 한글+영문, 쪽마다 표식).
`pdfrx 2.4.7` / Windows 릴리스 빌드에서 **8개 항목 전부 통과**.

| 검증 항목 | 결과 |
|---|---|
| 전체 쪽 로드 | 4쪽 · 5ms |
| 텍스트 추출 (한글+영문 혼합) | 1쪽 177자, 한글 O · 영문 O |
| 쪽 단위 정확도 | 4개 쪽의 표식이 모두 제자리 |
| 검색 — 한 곳에만 있는 낱말 | `[3]` (기대 `[3]`) |
| 검색 — 여러 쪽에 걸친 한글 낱말 | "검색" → `[1, 2, 4]` |
| 검색 — 없는 낱말 | 오탐 없음 |
| 문서 열기 · 쪽 수 | 4쪽 |
| 색인 경로 (뷰어 없이 전체 추출) | 4쪽 · 580자 · **1ms** |

### 반드시 기억할 것 — 점진 로드 함정

pdfrx 는 **점진 로드(progressive loading)** 를 쓴다. `PdfViewer` 가 뷰어를 띄운 시점
(`onViewerReady`)에는 **1쪽만 실제로 열려 있고 나머지 쪽은 껍데기**라
`page.loadText()` 가 조용히 **빈 문자열**을 준다. 예외도 안 난다.

첫 검증에서 2·3·4쪽이 전부 빈 값으로 나와 6개 중 3개가 실패했던 원인이 이것이다
(표본 PDF 자체는 pypdf 로 확인했을 때 4쪽 모두 정상이었다).

따라서 **검색 색인을 만들 때는 반드시 둘 중 하나를 한다**:

```dart
// 1) 뷰어의 문서를 쓸 때 — 모든 쪽을 명시적으로 로드한 뒤 추출
await doc.loadPagesProgressively();

// 2) 뷰어와 별개로 색인만 만들 때 (권장 — 실제 구현 경로)
final doc = await PdfDocument.openAsset(path, useProgressiveLoading: false);
```

### 아직 확인하지 않은 것

- **스캔본 PDF(텍스트 레이어 없음)** — 표본이 없어 미검증. `loadText()` 가 `null` 을
  반환하는 경로는 코드에 이미 대비해 두었다(`text?.fullText ?? ''`). 실제 스캔본으로
  "검색 불가"를 사용자에게 알리는 흐름은 MVP 때 확인한다
- **큰 문서(300쪽+) 색인 시간·메모리** — 4쪽 580자가 1ms 였으나 규모 검증은 별개다
- **Android 실기기** — Windows 데스크톱에서만 확인했다
- **캡처(영역 → PNG)·파일 피커(SAF)** — 이번 검증 범위 밖

## 5. 화면

1. **책장** — 최근 읽은 책 카드, 열기 버튼
2. **뷰어** — 본문. 탭하면 상·하단 도구막대 표시/숨김
3. **검색** — 입력, 결과 목록(쪽 번호 + 앞뒤 문맥)
4. **캡처 모드** — 영역 선택, 저장·공유
5. **책갈피** — 하이라이트·책갈피 목록, 눌러서 해당 쪽으로
6. **설정** — 넘김 방향, 두 쪽 보기, 테마, 복사 시 출처 붙이기

## 6. 성능 기준

|---|---|

| 페이지 넘김 | 끊김 없이(60fps) |
| 전체 검색(색인 후) | 0.5초 이내 |

## 8. 열린 질문

사용자 확인이 필요한 것들:

1. **넘김 방식** — 책처럼 가로 넘김이 기본인가, 세로 스크롤이 기본인가?
2. **스캔 PDF(이미지만 있는 책)** — 검색이 안 되는데, OCR을 나중에라도 넣을 것인가?
3. **캡처 이미지** — 저장 위치를 갤러리로 할 것인가, 앱 전용 폴더로 할 것인가?
4. **태블릿** — 두 쪽 보기를 MVP에 넣을 것인가, 다음으로 미룰 것인가?
5. **iOS** — 코드 호환만 유지할 것인가, 동시 출시할 것인가?
