## 2. 캐릭터 「EXA」 (엑사)

### 2.1 정체성

**EXA 는 앱 그 자체다.**
사용자가 앱을 열면 EXA 가 눈을 뜨고, 읽는 동안 함께 보고, 처리 중이면 생각하고, 끝나면 웃는다.
말풍선을 띄우고 조언하는 도우미 캐릭터가 아니다. **상태를 보여주는 얼굴**이다.

| 항목 | 설정 |
|---|---|
| 이름 | EXA (엑사) |
| 정체 | 매일 열리는 작고 단단한 창(window). 안에 렌즈 하나가 있다 |
| 성격 | 과묵함 · 성실함 · 참견하지 않음 |
| 말투 | 말하지 않는다. 눈으로만 표현한다 (텍스트는 UI 카피가 담당) |
| 감정 폭 | 좁다. 과장된 기쁨/슬픔 없음. 상태를 알릴 뿐 |
| 금지 | 팔다리, 입, 눈썹, 말풍선, 3D, 그라데이션, 아웃라인 픽셀아트 |

### 2.2 형태 규칙 (기하 구조)

64×64 그리드 기준. **이 수치를 벗어난 EXA 는 EXA 가 아니다.**

```
바디(스퀘어클)   x=2  y=2   w=60 h=60  rx=17      ← 앱 타일
바이저(렌즈 슬롯) x=13 y=26  w=38 h=12  rx=6       ← 얼굴
동공(신호)        cx=32 cy=32 r=4.5                ← 상태를 나타내는 유일한 요소
```

- **동공만 움직인다.** 바디와 바이저는 절대 변형하지 않는다 (완료·휴면 표정만 예외)
- 스트로크를 쓰지 않는다. **면(fill)으로만** 구성한다 → 어떤 크기에서도 뭉개지지 않는다
- 최소 사용 크기 **16px**. 16px 에서는 동공 r=1.4, 바이저 h=3 으로 단순화한 `favicon-16.svg` 를 쓴다
- 여백(clear space): 바디 높이의 **25%** 를 사방에 비운다

### 2.3 표정 세트 (7종) — 앱 상태와 1:1 대응

| 파일 | 이름 | 동공 상태 | 언제 쓰는가 |
|---|---|---|---|
| `exa-idle` | 기본·대기 | 정중앙 | 앱 아이콘, 스플래시, 평상시 |
| `exa-read` | 읽는 중·스캔 | 오른쪽 + 잔상 2개 | 인덱싱, 페이지 로딩, 스캔 진행 |
| `exa-think` | 생각 중·처리 | 우상단 + 떠오르는 점 2개 | AI 요약, OCR, 영상→북 변환 중 |
| `exa-found` | 찾음·결과 | 링 + 중심점 (조리개) | 검색 결과 있음, 하이라이트 저장됨 |
| `exa-done` | 완료·성공 | 바이저가 호(∪)로 변형 | 작업 완료 토스트, 완독 |
| `exa-error` | 오류·실패 | 동공이 납작한 바 | 실패 다이얼로그, 빈 결과 |
| `exa-sleep` | 휴면·백그라운드 | 바이저가 가는 선 | 백그라운드 작업, 오프라인 |

**애니메이션 규칙**
- 동공 이동: `250ms · easeOutCubic`. 표정 전환: `180ms · easeInOut`
- 읽는 중(`read`)만 루프. 나머지는 **1회 재생 후 정지**
- 반복 애니메이션은 대기 상태에서 절대 돌리지 않는다 (배터리 · 시선 강탈)
- 접근성: `MediaQuery.disableAnimations` 가 true 면 전부 정지 상태로 표시

### 2.4 제품별 변형 규칙

**바디·바이저·동공 기하는 고정하고, 액센트 색과 하단 힌트 글리프만 바꾼다.**

| 제품 | 액센트 | 힌트 글리프 |
|---|---|---|
| EXANSYS (모회사) | Signal `#4CC2FF` | 없음 |
| **북뷰 / BookViewer** | Amber `#FFC24B` | 하단에 펼친 책 실루엣 (y=41~47) |
| (향후 앱) | 각자 1색 | 각자 1글리프 |

> 새 앱을 만들 때 **캐릭터를 새로 그리지 않는다.** 색 하나와 글리프 하나만 정한다.
> 이것이 EXANSYS 앱군이 한 가족으로 보이는 유일한 이유다.

|---|---|---|
| `amber` | `#FFC24B` | **브랜드 액센트** — 아이콘, 캐릭터 동공, 일러스트, 스플래시 |
| `amber-deep` | `#C98A1E` | 라이트 배경 위 텍스트/아이콘용 앰버 (대비 확보) |

> ⚠ **중요한 제약**: `#FFC24B` 는 흰 배경 대비 약 **1.8:1** 이라 텍스트·포커스링·아이콘 버튼에

> 브랜드색과 기능색을 분리하는 것이 이 시스템의 핵심 규칙이다.

## 5. 형태 · 간격

- 간격 스케일: **4 / 8 / 12 / 16 / 24 / 32 / 48**
- 모서리: 버튼 `10`, 카드 `14`, 바텀시트 `20`, 앱아이콘 `14/64` 비율
- 최소 터치 타깃 **48×48dp** (모바일) / 클릭 타깃 32px (데스크톱)
- 그림자 대신 **표면 밝기 차이**로 층을 표현한다 (다크 우선 설계이므로)

### UI 아이콘 시스템
- 세트: **Lucide** (ISC 라이선스, 무료 배포 가능)
- 24×24 그리드, stroke 1.75, 라운드 캡
- **캐릭터와 UI 아이콘은 스타일이 다르다.** EXA 는 면(fill), UI 아이콘은 선(stroke).
  섞지 않는다 — 섞는 순간 화면이 지저분해진다
- 예외: 앱 내에서 EXA 가 등장하는 곳은 **빈 상태 · 로딩 · 완료 토스트 · 스플래시 · 설정 정보** 5곳뿐

## 6. 적용 가이드

### 6.1 앱 아이콘
- Android: 어댑티브 아이콘. **배경 레이어 = ink 단색**, 전경 레이어 = 바이저+동공+책힌트
  (전경은 안전영역 66% 안에 넣을 것 — 마스킹으로 잘린다)
- iOS: 라운드 처리는 OS 가 하므로 **정사각 풀블리드**로 제출
- 데스크톱: `.ico` / `.icns` 는 16·32·48·256 전부 생성. 16px 는 `favicon-16` 단순화 버전 사용

### 6.2 스플래시
ink 단색 배경 + 화면 중앙 EXA `idle` (화면 폭의 22%) + 하단 워드마크.
**로딩 스피너를 넣지 않는다.** 대신 동공이 `idle → read` 로 한 번 움직인다.

### 6.3 빈 상태 · 로딩 · 오류
| 상황 | EXA 표정 | 카피 톤 |
|---|---|---|
| 서재가 비었음 | `idle` | "아직 책이 없습니다" + 추가 버튼 |
| 검색 결과 없음 | `error` | "찾지 못했습니다" + 검색어 수정 힌트 |
| 인덱싱 중 | `read` | "검색 준비 중 · 78%" |
| 영상→북 변환 중 | `think` | 단계명 표시 (자막 받는 중 / 슬라이드 찾는 중 …) |
| 완료 | `done` | 4초 토스트 |
| 오프라인 | `sleep` | "서버에 연결할 수 없습니다" |

### 6.4 exansys.net 적용
- 히어로: ink 배경 + EXA `idle` 대형 + `THINK AT EXA SCALE`
- 스크롤 시 동공이 마우스/스크롤 방향을 아주 미세하게 따라간다 (±3px 이내). 그 이상은 유치해진다
- 제품 섹션마다 해당 앱의 EXA 변형(색+글리프)을 배치 → 앱군이 한 가족임을 시각적으로 증명
- 파비콘: `favicon-16.svg`

## 8. 금지 사항

1. 캐릭터에 팔·다리·입·눈썹을 붙이지 않는다
2. 바디/바이저 기하를 변형하지 않는다 (`done`, `sleep` 표정만 예외)
3. 그라데이션·3D·드롭섀도우를 캐릭터에 적용하지 않는다
4. 앰버(`#FFC24B`)를 버튼 텍스트·포커스링·본문에 쓰지 않는다 (대비 미달)
5. 새 앱마다 새 캐릭터를 그리지 않는다 — 색 1개 + 글리프 1개만 정한다
6. EXA 를 5곳(빈상태·로딩·완료·스플래시·정보) 밖에서 남발하지 않는다
7. 워드마크의 마크와 글자 사이 간격을 임의로 조정하지 않는다
